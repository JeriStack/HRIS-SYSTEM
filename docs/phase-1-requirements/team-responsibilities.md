## 1. Project Role Definitions & Responsibility Areas

To ensure clear accountability across the 16-phase development lifecycle, project responsibilities are mapped to standard technical functions. Placeholder designations (`[Team Member 1]` to `[Team Member 8]`) are utilized until student group assignments and individual allocations are confirmed by the team.

| Role Identifier | Functional Area | Primary Scope & Deliverables |
| :--- | :--- | :--- |
| **ROLE-COORD** | Project Coordination & Documentation | Schedule tracking, meeting facilitation, milestone verification, SRS compilation, user manual preparation. |
| **ROLE-ARCH** | System Architecture & Analysis | Layered architecture definition, MVC routing design, component boundaries, flowcharts, use cases. |
| **ROLE-UIUX** | UI/UX & Frontend Design | Design system, wireframes, navigation flow, responsive CSS layout, user feedback states (alerts, modals). |
| **ROLE-AUTH** | PHP Core & Security Engineering | Session management, password hashing, role-based authorization middleware, CSRF security, error handling. |
| **ROLE-HRIS** | HRIS & Leave Workflow Engineering | Employee CRUD, department/position management, leave calculation logic, transaction-safe leave approval. |
| **ROLE-DSA** | DSA Algorithm Engineering | Native PHP implementation of custom data structures (Array, Stack, Queue, LinkedList, HashTable, BST) and sorting/searching algorithms. |
| **ROLE-DB** | Database Architecture & Integrity | Schema modeling, ERD generation, SQL migrations/DDL, foreign keys, transaction constraints, indexing. |
| **ROLE-QA** | Quality Assurance & Testing | Unit testing, integration testing, benchmark execution, defect tracking, Git/GitHub repository administration. |

## 2. RACI Responsibility Assignment Matrix

**RACI Key:**
* **R (Responsible):** The role that executes the task.
* **A (Accountable):** The role with final approval and ownership.
* **C (Consulted):** The role that provides key input or review.
* **I (Informed):** The role kept updated on progress.
